# 插件库管理器 (Blender Plugin Library Manager)

给 Blender 加一个完整的**插件资源管理器**：所有插件集中存放在一个库文件夹，
在 Blender 里直接做分类、备注、标签、收藏、启停、更新检测，并且**升级 Blender 后继续沿用**。

## 它解决什么问题

你在用 Blender 时常遇到：

- 下载的插件散落在 `scripts/addons`、多个自定义脚本目录、多个扩展仓库里，分不清哪个在用；
- 不知道某个插件是否已启用、版本是多少、是否比官方仓库里的旧；
- 换了 Blender 版本后，插件和分类信息要重新找、重新记。

这个插件把上面这些收敛成**一个库 + 一个面板**。

## 核心设计

### 1. 所有插件集中到一个库文件夹

插件库路径保存在每台电脑自己的本机配置中，不再随 Blender 同步偏好传播。库内部结构自动创建：

```
BlenderPluginLibrary/
├── addons/        传统插件   <库>/addons/<插件名>
├── extensions/    扩展插件   <库>/extensions/<插件id>
├── inbox/         投放区     把插件文件夹或 zip 丢这里
├── trash/         回收站     移除的插件移到这里
└── .pm/           内部数据   schema 2 library.json, backups/, archive/
```

### 2. 挂载方式（关键：不依赖软链接）

Windows 上给目录建软链接需要管理员权限，容易失败。本插件改用 Blender **原生支持的两种机制**：

- **脚本目录（Script Directories）**：把库根目录注册进去，于是 `<库>/addons/*` 全部成为传统插件源；
- **扩展仓库（Extension Repository）**：把 `<库>/extensions` 注册成本地扩展仓库，于是扩展插件也被纳入。

两者都是 Blender 偏好设置里的标准项，**不写注册表、不需要管理员、升级 Blender 后点一下「启用/修复插件库」即可重新挂载**。

### 3. 手动扫描投放区

把插件文件夹或 zip 放进 **`<库>/inbox/`**（或直接放库根目录），然后在面板点
**「扫描并导入」**。每次扫描都会完整检查这两个位置，并逐项给出结果：

- **插件文件夹** → 识别类型（有 `blender_manifest.toml` 视为扩展插件，否则视为传统插件），搬到 `addons/` 或 `extensions/`；
- **zip 插件包** → 解压、定位内部的插件根目录、归档，成功后删掉 zip；
- **自动备注与标签** → 首次导入时用插件自带描述填充备注、用 manifest 的 tags 填充标签。分类**不会**自动套用插件自带的值，统一归入「未分类」，由你自己整理；
- 同名插件自动去重。

**错误报告**：扫描结果分「导入 / 跳过 / 失败」三种状态，每条都带插件名、
类型、来源完整路径和具体原因。有失败项时自动弹出报告，可**复制到剪贴板**或写入
`<库>/.pm/last_scan.log`。区分规则：目录里出现 `blender_manifest.toml` 或
`__init__.py`（本意是装插件但内容有问题）→ 记为**失败**；纯粹无关的文件夹 → 记为跳过。

### 4. 元数据与 Blender 版本解耦

分类、备注、别名、标签、收藏、自启和便携插件身份写在 `<库>/.pm/library.json` 的 schema 2 数据库中，
和 Blender 安装版本无关。启用状态、模块名、兼容性和错误保存在本机状态目录，不会同步覆盖其它电脑。

2.0.0 不迁移旧版数据库。首次遇到旧 `library.json` 时会先原样归档到 `.pm/archive/` 并设为只读，再创建全新数据库。

### 5. 两套插件体系统一识别
Blender 4.2+ 同时存在两种插件：

| 类型 | 判定依据 | 归属目录 | 启用模块名示例 |
|------|----------|----------|----------------|
| 传统插件 addon | `__init__.py` 里有 `bl_info` | `<库>/addons/` | `LegacyDemo` |
| 扩展插件 extension | 有 `blender_manifest.toml` | `<库>/extensions/` | `bl_ext.pmlib.ext_demo` |

管理器对两者一视同仁：都能分类、启停、检测更新。

### 6. 自动规避常见的加载失败

Blender 对扩展插件很挑剔，以下情况会被静默跳过（扩展列表里干脆不出现）：

- **目录名不是合法标识符**（含空格、连字符、括号等）。扩展的模块名是
  `bl_ext.<仓库>.<目录名>`，所以目录名必须是合法 Python 标识符。导入时管理器会
  自动把 id 净化为合法目录名（如 `Straighten UV` → `Straighten_UV`）。
- **manifest 字段不合规**，例如 `license` 写成字符串而非列表、
  缺少 `blender_version_min` 等。

管理器会在导入时就校验 manifest，并在插件详情的「⚠」行标出问题，避免"装进去了却用不了"。

> 传统插件不受此限制：它的模块名来自路径加载，含空格和中文的目录名都能正常工作。

## 安装

任选一种。

### 方式 A：一键脚本（推荐，覆盖本机所有 Blender 版本）

```powershell
powershell -ExecutionPolicy Bypass -File install.ps1
```

脚本会把 `bl_plugin_manager` 复制到每个版本的
`%APPDATA%\Blender Foundation\Blender\<版本>\scripts\addons\`，不需要管理员权限。

### 方式 B：从磁盘安装 zip

```bash
python build_zip.py
```

然后在 Blender 中 `编辑 > 偏好设置 > 插件 > 安装…`，选择 `dist/bl_plugin_manager-<version>.zip`。

### 启用

`编辑 > 偏好设置 > 插件`，搜索 **Plugin Library**（或「插件库」）勾选启用。
之后在 **3D 视图按 N**，右侧边栏出现 **「插件库」** 标签。

> 若库目录已存在，启用插件时会**自动重新挂载**，升级 Blender 后只需启用本插件即可。

## 使用

### 首次：设置库并挂载

在 **3D 视图按 N →「插件库」** 标签顶部就是「插件库位置」区，点 **选择目录**：

- 选一个**空文件夹**或**不存在的新路径** → 自动创建空库并挂载；
- 选一个**已经装好插件的目录** → 自动识别原有 `addons/`、`extensions/`，直接接管；
- 选一个**里面散落着插件文件夹或 zip 的目录** → 自动把它们收编进 `addons/`、`extensions/` 再挂载；
- 若不小心**选中了某个插件本身的文件夹**，会提示改选它的上一级目录；
- 若选中的是**非空、又不含任何插件**的目录（例如资产库），会拒绝操作，避免误把无关文件夹改造成插件库。

选完即自动挂载，无需再去偏好设置。面板顶部会显示当前库路径与挂载状态；
「启用/修复」用于挂载失效时一键修复。

> 也可以在 `编辑 > 偏好设置 > 插件 > 插件库管理器` 里直接填路径。

### 把现有插件收编进来

侧边栏「迁移与工具」面板：

- 点 **扫描现有插件** — 自动扫描你当前 Blender 的脚本目录与本地扩展仓库，列出可收编的插件数量；
- 点 **收编全部** — 把它们导入插件库。

> 收编默认是**复制**（原目录保留，更安全）。想直接搬走可在弹窗里勾选「移动而非复制」。
> Blender 自带的官方/系统仓库（`blender_org`、`system` 等）会被自动跳过，不会误搬。

### 日常：手动扫描投放区

把新下载的插件**文件夹或 zip** 拖进 `<库>/inbox/`，然后点击面板中的
**「扫描投放区」**（或「扫描并导入」）才会处理并出现在列表里。投放区不会后台
自动监视；文件正在复制或下载时，等文件写入完成后再启动扫描，以免导入不完整的包。

### 面板功能

- **列表**：每行左侧方块即启停开关（实心=已启用）；`★` 表示收藏；右侧显示版本号；
  上传图标表示检测到可更新，红色警告表示文件已丢失。
- **过滤器**：只看收藏 / 只看可更新 / 只看已启用 / 搜索框。
- **分类**：分类**完全由你自己创建**，扁平结构、不嵌套，每个插件只属于一个分类。
  下方网格按分类筛选；可新建、重命名、删除分类；在插件详情用「移入分类…」下拉把
  插件归入某个分类，或移回「未分类」。
  内置的插件自带元数据分类（如 `3D View`、`Animation`）不会自动灌进你的分类列表；
  需要时可在详情点「采用自带分类」单独取用，或用「清理自动分类」把历史遗留的
  自动分类一次性收回（**只影响你从未手动改动过的**，你自己建的分类与归属会完整保留）。
- **详情**：显示名称 / 实际插件名、类型、版本、最新版本、最低 Blender 版本、作者、模块名、备注；
  可启用/停用、编辑信息、打开所在文件夹、移除（进回收站）。
- **导入**：导入文件夹 / 导入压缩包。
- **更新检测**：读取所有扩展仓库缓存索引里的最新版本号，与库内插件比对并标记。
- **一键测试插件支持**：点一下按钮，逐个尝试加载插件，测出哪些能在当前 Blender 下
  正常工作。结果在列表右侧直接用符号标出：**✓** 支持、**✗** 不支持（红色）、
  **?** 尚未测试；点 ✗ 的插件在详情里能看到具体失败原因（如缺少 `bgl` 模块、
  Python 版本不匹配等）。这样不用等真正用到时才发现插件不可用。

  > 判定优先级：**实测结果** > 插件声明的版本范围 > 未知。因为绝大多数插件并未
  > 声明"最高支持版本"（本库 152 个里仅 1 个声明），所以实测才是可靠依据；
  > 兼容结论会按当前 Blender 版本**实时计算**，换版本后看到的始终是准确结果。

### 在线商店与在线更新

内置了 Blender 官方商店（`extensions.blender.org`）的浏览、安装与更新：

- **浏览扩展**：面板「在线商店」区点 **浏览/安装扩展**，弹出列表可搜索（按名称、
  描述、作者、标签）、可按「仅未安装 / 仅兼容当前版本」过滤，并直接点 **安装**；
- **安装**：下载官方压缩包（带 sha256 校验）→ 自动识别类型归档到 `addons/` 或
  `extensions/`；
- **更新**：库内插件若商店有更高版本，列表会标出并可 **更新**——更新是**原地替换**，
  你的分类、备注、显示名称、收藏、自启标记全部保留，启用状态也会自动恢复；
- **一键更新全部**：一次把所有检测到可更新的插件升级到最新版；
- **刷新目录**：目录来自 Blender 自带的仓库索引，点刷新即联网同步（也可用
  Blender 原生的「检查更新」）。

> 下载需要联网。若商店请求失败，多半是索引未同步，先点「刷新商店目录」。

### 与 Blender 官方商店统一（重要）

默认情况下，Blender 官方商店仓库（`blender_org`）指向用户配置目录，与本插件库
是**两套目录**——于是会出现"在官方面板下载的插件，本插件管不到"、"官方面板一直提示
更新"的情况。

点面板里的 **让官方商店使用本插件库** 可一键统一：

- 把官方商店仓库的目录**指向插件库的 `extensions/`**，并移除本插件早年另建的仓库；
- 把官方目录里**已安装的扩展迁移进库**（含启用状态）；
- 开启 `偏好设置 > 系统 > 允许联网访问`（官方安装/更新所需）。

统一之后：**Blender 自己的「获取扩展」面板与本插件操作同一批文件**。
无论从哪边安装/更新，插件都落在插件库中，由本插件统一管理分类、备注、启停与更新检测，
不再出现两套插件或重复提示。

> 该设置会持久保存（重启后仍生效）。想还原成 Blender 默认行为，可在
> `偏好设置 > 获取扩展 > 仓库` 里把 `extensions.blender.org` 的目录改回默认。

### 两种名称（实际名 / 显示名称）
每个插件有两个名称，互不干扰：

| 名称 | 来源 | 是否可改 |
|------|------|----------|
| **实际插件名** | 插件自带的元数据（`bl_info` / manifest） | 只读，仅作标识 |
| **显示名称** | 你自己设的别名 | 可随时改、可清除 |

界面里**显示名称是主体**；设了别名后，列表会以灰色小字在名称后标出实际插件名，
两者一眼可辨。比如把 `A.N.T.Landscape` 的显示名称设为「地形生成」，
列表就显示 `地形生成（A.N.T.Landscape）`。

用途：给英文插件起中文名、把冗长名字缩短，方便查找和启停。
设置方式：选中插件 → 详情区 **设置显示名称…**；旁边的 **清除别名** 可恢复为实际名。
搜索框对两个名称都会匹配。

### 启动控制（自启标记）

每个插件有一个独立的**自启标记**，和「当前是否启用」是两回事：

- **启用开关**（列表左侧方块）＝ 当前会话是否加载；
- **自启标记**（列表第三个圆点 / 详情区）＝ 下次启动 Blender 时是否自动加载。

用法是「常用插件标自启，其余按需加载」。在「迁移与工具」面板里：

- **立即同步自启状态** —— 把自启标记立刻应用（勾选后可选「同时停用未标记自启的插件」）；
- **启动时按「自启」标记同步** —— 开启后每次启动 Blender 自动应用，默认**只启用**标记项，
  不会主动停用任何插件，避免误关。

### 批量操作

列表每行最左侧是勾选框。勾选多个后，在「批量操作」区可一键完成：
批量**启用 / 停用**、批量**归入分类**、批量**设为自启 / 取消自启**。

### 视口标题栏快捷入口

3D 视口标题栏右侧会出现插件库图标，点开后直接列出该分类下的插件，点击即可
启用/停用，并显示各自的自启标记——不用打开侧边栏就能快速切换。

### 失败原因记录

插件启用失败时（例如插件自身 `register()` 报错），失败原因会记录到该插件的
`last_error`，在详情区以红色显示，方便定位是哪个插件、什么原因装不上。

## 升级 Blender 之后怎么办

1. 用 `install.ps1` 把本插件装到新版本（脚本会自动覆盖本机所有版本目录）；
2. 新版本里启用本插件 —— 若库目录已存在，它会**自动重新挂载**；
3. 若库路径丢失，在偏好设置里重新填同一个路径，点 **启用/修复插件库**。

因为库目录与 `library.json` 都在 Blender 之外，分类、备注、启停记录全部照旧。

### 撤销挂载

侧边栏的「卸载挂载」按钮可把库从 Blender 的脚本目录/扩展仓库中撤下（**不删除任何插件文件**），
适合临时想让 Blender 回到"干净"状态时使用；再次点「启用/修复插件库」即可恢复。

## 目录说明

```
bl_plugin_manager/
├── __init__.py      插件入口、注册/注销
├── constants.py     常量与目录约定
├── preferences.py   偏好设置（库路径、启动同步、列表数据项）
├── db.py            library.json 读写（分类/备注/标签/收藏）
├── scan.py          插件识别与元数据解析（manifest / bl_info / zip）
├── bridge.py        与 Blender 桥接：脚本目录、扩展仓库、启停、刷新
├── library.py       导入、归档、备份、同步、移除
├── store.py         在线商店：浏览/搜索/下载/安装/更新
├── header.py        3D 视口标题栏快捷入口
├── updates.py       更新检测与版本比对
├── migrate.py       扫描并收编现有插件
├── watcher.py       投放区手动扫描与结果报告
├── items.py         列表数据同步（供 UIList 显示）
├── operators.py     全部操作符
└── ui.py            N 面板与 UIList
```

## 注意事项

- 需要 **Blender 4.2 及以上**（扩展插件体系与 `blender_manifest.toml` 从 4.2 开始）；
  传统插件在更早版本也能用，但本插件整体按 4.2+ 设计。
- 「收编」与「导入」默认复制，会额外占用磁盘；确认无误后可自行删除旧目录。
- 移除插件是移入 `<库>/trash/`，不是直接删除，可手动找回。
- 少数插件自身 `register()` 会报错，启停时会在状态栏提示错误信息，但不会影响管理器本身。
