# Blender 插件库管理器 2.5

面向 Blender 4.2+ 的便携插件库。它统一管理传统插件、扩展插件与 Blender 内置插件，将「分类筛选」与「工作预设」职责彻底拆分，提供记住上次/干净启动二选一启动策略、手动启用温和提示、原生界面中英双语显示名、备注、扩展仓库和自定义脚本目录，同时把“跨电脑共享的插件资料”与“每台电脑的安装位置和启用行为”严格分开。

## 关键行为

- 插件文件集中存放在一个可同步或可迁移的库目录。
- **总插件数据库**（`.pm/catalog.json`）以稳定插件 ID 记录插件身份，别名、分类、标签、备注、收藏等资料跟随库迁移。当前行为和验收标准见 [现行需求](docs/REQUIREMENTS.md)。
- 各电脑安装的插件数量和目录名可以不同：扫描时按 manifest id / 插件声明名 / 目录名自动匹配到同一条资料库记录，自动套用别名与分类。
- 每台电脑有稳定设备 ID、可编辑设备名称和独立插件启用清单。
- **自启标记与启用状态属于本机行为**，不随总插件数据库同步，避免各电脑插件数量不同时互相覆盖。
- 每台电脑可使用不同盘符或网络路径，不会把 A 电脑的绝对路径覆盖到 B 电脑。
- 管理开启时，Blender 原生“获取扩展 / 插件 / 文件路径”中的相关配置由本插件接管并双向同步。
- 管理停止时，只恢复扩展仓库、自定义脚本目录和库内插件启用状态；不会重置主题、快捷键、语言、渲染、资产库或其它偏好。
- 插件不会调用 Blender 的全局偏好保存或工厂重置操作，也不会自动修改“允许联网访问”。
- 「一键测试插件支持」以分步任务运行：界面在测试期间保持可交互，可随时取消，进度与结果即时可见。

## 数据布局

```text
BlenderPluginLibrary/
├── addons/                         传统插件
├── extensions/                     Blender 扩展
├── inbox/                          待导入文件夹或 ZIP
├── trash/                          可恢复移除区
└── .pm/
    ├── catalog.json                总插件数据库（跨电脑同步的插件资料）
    ├── devices/
    │   ├── <device-id-a>.json      设备 A 的启用意图、仓库与脚本路径
    │   └── <device-id-b>.json      设备 B 的独立配置
    ├── backups/
    └── archive/                    旧版 library.json 归档
```

本机文件（不放进同步库）：

```text
%LOCALAPPDATA%/BlenderPluginManager/
├── machine.json                    稳定设备 ID、名称、本机库路径、接管状态
└── state/<library-id>/<环境>.json  模块名、是否启用、自启标记、加载结果、错误，
                                    以及 plugin_id → 库内相对路径的本机绑定
```

### 三层数据职责

| 数据 | 位置 | 是否跨电脑同步 |
|---|---|---|
| 插件身份、别名、分类、标签、备注、收藏 | `.pm/catalog.json`（总插件数据库） | 是 |
| 启用意图、扩展仓库、脚本目录 | `.pm/devices/<设备ID>.json` | 随库同步，每设备一份 |
| 安装位置、已装版本、兼容范围、模块名、启用状态、自启标记、加载结果 | 本机状态目录 | 否 |

`catalog.json` 只保存可跨电脑解释的数据，绝不写入绝对/相对路径、模块名、是否启用或自启。写入采用临时文件、`fsync` 与原子替换；损坏时保持只读并拒绝覆盖。

## 插件匹配与连线

总插件数据库以 `plugin_id`（如 `addon:mesh-tools`、`ext:prompt-tools`）为键，而不是库内路径。扫描时按以下顺序连线：

1. 扩展 manifest 的 `id`（扩展插件全局唯一，最可靠）；
2. 插件声明的名称（`bl_info['name']` / manifest `name`）；
3. 目录名（弱线索）。

每条记录会累积历史名称与目录名，以便同一插件改名或移动后重新关联。扩展和传统插件分别匹配，两个明确不同的扩展 manifest ID 不会因使用同一目录或名称而合并。传统插件没有 manifest ID，名称与目录用于辅助识别。

各电脑安装的插件不同时，本机只显示自己实际安装过（有绑定）的插件；总资料库仍保留其它电脑安装的条目，随时可被匹配。

## 安装

从 ZIP 安装：

```powershell
python build_zip.py
```

在 Blender 中打开“编辑 → 偏好设置 → 插件 → 从磁盘安装”，选择最新的 `dist/bl_plugin_manager-<版本>.zip`。

### GitHub 更新

首次安装带更新入口的 2.3.1 或更新版本后，在“编辑 → 偏好设置 → 插件 → 插件库管理器”点击 **检查并下载 GitHub 更新**。Blender 需允许联网。下载时会核对正式 Release 的版本与 SHA-256，安装在下次启动时生效，旧插件程序保存在用户插件目录的 `.bl_plugin_manager-previous-…` 下。该操作更新的是插件库管理器本身。

维护者发布新版时，将 `bl_plugin_manager/constants.py` 和 `bl_plugin_manager/__init__.py` 中的版本改为同一个值并提交。上传该提交及同版本的标签（如 `v2.3.2`）后，GitHub Actions 会自动验证、打包，并发布带 ZIP 的正式 Release。普通提交上传后，已安装的插件会继续使用上一个正式 Release。

本机开发安装前先关闭所有 Blender 窗口，再运行：

```powershell
powershell -ExecutionPolicy Bypass -File install.ps1
```

安装脚本使用临时目录和上一版本回滚目录进行交换；若复制或编译失败，会尝试恢复旧版本。

## 首次使用

1. 在“编辑 → 偏好设置 → 插件”中启用“插件库管理器”。仅启用管理器不会自动接管 Blender 配置。
2. 在 3D 视图按 `N`，打开“插件库”，选择目录并查看连接预览。设备名称可在插件偏好中修改。
3. 点击“启用管理”。管理器会创建或迁移总插件数据库、扫描插件并创建当前设备配置。
4. 首次启用会把当前原生扩展仓库和自定义脚本目录收编进当前设备配置，同时保证库的 `addons/` 与 `extensions/` 可被 Blender 发现。

选择目录时，空目录会初始化成新库；已有库会直接识别；散放的插件可收编。插件本身或与插件无关的非空目录会被拒绝，避免误改文件。

### 从旧库升级

首次确认连接 1.x schema 1 或 2.0/2.1 schema 2 的库时，`.pm/library.json` 会迁入总资料库，保留别名、分类、标签、备注、收藏，并将自启迁到本机状态。成功后旧文件归档到 `.pm/archive/`。损坏或不支持的版本保持只读并保留原件。

## 多电脑同步

每台电脑第一次运行都会生成不同的稳定设备 ID。设备名称可在插件偏好或主面板中修改，改名不会改变 ID。

- A 电脑可使用 `D:\BlenderLibrary`，B 电脑可使用 `X:\同步\BlenderLibrary`。
- 两台电脑共享 `catalog.json` 中的别名、分类、备注和插件信息。
- 两台电脑分别读取 `.pm/devices/<各自ID>.json`，自动恢复各自的启用插件列表和本地地址。
- 各电脑安装位置、模块名、启用状态与自启标记互不覆盖；某插件暂时不存在或加载失败时，其“启用意图”仍保留，文件恢复后可再次应用。
- 设备数不硬限制为三台。

共享资料须包含隐藏目录 `.pm/` 中的资料库和设备配置。安装文件可以分别维护；如果同步了整个库，移除、恢复或更新文件也可能传播到另一台电脑。本机配置和运行状态应留在各电脑。

## 接管与停止

“启用/修复插件库”进入接管状态：

- 原生面板新增或修改的扩展仓库、脚本目录会写入当前设备文件；
- 在原生插件面板或本插件中改变库内插件启用状态，会进入当前设备启用清单；
- 管理器每两秒做一次字段比较，仅在实际变化时写文件；
- 库根脚本目录与库扩展目录是运行必需绑定，被原生面板删除后会自动补回。

“卸载挂载”或停用本插件会先保存当前设备配置，然后：

- 停用插件库内的插件；
- 删除自定义脚本目录；
- 删除自定义扩展仓库，并把官方仓库恢复到 Blender 默认 URL 与默认目录行为；
- 保留 Blender 内置仓库；
- 不修改联网权限及任何其它偏好。

停止状态保存在本机。再次加载管理器仍保持停止；必须点击“启用/修复插件库”才会重新接管并恢复当前设备清单。

已接管的库暂时不可访问时进入离线状态，保留现有脚本目录、仓库和设备意图，待路径恢复后可重连。

## 插件管理

- 将插件文件夹或 ZIP 放进 `<库>/inbox/`，点击“扫描投放区”。
- 传统插件进入 `addons/`；带 `blender_manifest.toml` 的扩展进入 `extensions/`。
- 扩展 ID 会转换为合法 Python 标识符，manifest 会在导入前校验。
- 支持搜索、收藏、扁平分类、别名、备注、批量启停、更新检查和回收站移除。
- 移除将文件移入库内回收站并解除本机绑定，保留共享资料。可用“从回收站恢复”回到原位置；2.2 创建的旧回收站目录仍可手动恢复。
- 「一键测试插件支持」为分步任务：侧栏显示 `已完成 / 总数`、当前插件名与进度条，界面在测试期间保持可交互；可随时「取消」，取消在当前插件处理结束后生效，已完成结果保留。测试范围可选「继续未完成项」（默认）或「全部重新测试」。
- 兼容性实测会真实运行第三方插件代码，建议只在可信插件和已保存工程中使用。
- 在线安装需要用户自行在 Blender 系统设置中允许联网。商店分别显示各仓库报价；已安装的扩展默认从原来源更新，来源未知或变更时需单独确认。安装和更新支持预览、取消下载及重试失败项。

## 界面入口

- **3D 视图侧边栏（N → 插件库）**：高频插件管理——库连接状态、搜索筛选、插件列表、插件详情、批量操作、导入、在线商店、更新、扫描报告，以及兼容性测试入口与运行时进度。
- **编辑 → 偏好设置 → 插件 → 插件库管理器**：低频配置与维护——设备名称、库路径、启用/修复与卸载挂载、刷新、诊断、启动同步策略、迁移收编、清理失败插件残留、清除更新标记，以及官方商店目录关联。
- 3D 视图顶部栏不提供「插件库」按钮或分类快捷入口（2.1.0 起移除）。

## 安全边界

- 不调用 `save_userpref`、`read_factory_settings`、`read_homefile` 或 `read_userpref`。
- 不复制或覆盖真实 `userpref.blend`。
- 不按名称猜测并清理未知来源。
- 所有数据库写入采用临时文件后原子替换；损坏的数据库保持只读，不会静默覆盖。
- 总插件数据库拒绝写入任何本机字段（路径、模块名、启用状态、自启）。
- 插件记录路径必须落在库的 `addons/` 或 `extensions/` 容器内。
- 测试运行器会验证全部 Blender 与插件状态路径位于一次性隔离目录，并检查真实偏好文件哈希不变。

## 验证

```powershell
# 纯 Python：单元测试 + 静态入口检查（不需要 Blender）
python -m unittest discover -s tests -p "test*.py" -q
python _test/check_ui.py
python _test/audit_features.py

# Blender 隔离回归与端到端（需 Blender 4.2+，可用 BLENDER_EXE 指定可执行文件）
powershell -ExecutionPolicy Bypass -File _test/run_regressions.ps1
powershell -ExecutionPolicy Bypass -File _test/run_e2e.ps1
powershell -ExecutionPolicy Bypass -File _test/run_regressions.ps1 -Suite store
powershell -ExecutionPolicy Bypass -File _test/run_regressions.ps1 -Suite ui
```

两套 Blender 启动器会把配置、脚本、TEMP、本机配置和本地状态全部指向一次性临时目录，因此不会改动真实插件库或用户偏好。`_test/test_ui_smoke.py` 用模拟布局真实执行各面板与列表行的 `draw`，需在 Blender 内单独运行。

详细设计与审计见 `docs/PLUGIN_MANAGER_ARCHITECTURE_AUDIT.md`、`docs/superpowers/specs/2026-09-13-machine-local-library-path-design.md`、`docs/superpowers/specs/2026-09-18-master-catalog-design.md` 和 `docs/superpowers/specs/2026-09-15-compatibility-task-and-settings-design.md`。

## 2.5.6 优化

- **优化「获取扩展」与在线商店流畅度**：
  - `native_names` 新增 `warm_from_db` 预热与 O(1) 字典映射结果记忆化缓存（30s TTL，改名/刷新立即失效），彻底消除每次重绘重复复制字典、创建 namedtuple 或回盘读 `X:` 库的开销。
  - 偏好设置新增独立开关「在『获取扩展』界面也显示中文别名」，可按需单独关闭获取扩展界面挂钩。
  - 分页在线商店弹窗（`浏览/安装`，每页 12 项）缓存搜索结果，避免鼠标移动时重复遍历 1,400+ 远程目录。

## 2.5.5 修复与性能大幅优化

- **修复退出 Blender 后管理状态丢失**：区分「退出 Blender / 重载脚本（`addon_utils.disable_all`）」与「在偏好设置中显式停用本插件」——正常退出 Blender 不再撤销插件库挂载或将 `management_enabled` 置为 `false`，下次打开自动恢复管理状态。
- **优化 Blender 启动与打开偏好设置面板速度**：
  - `register()` 阶段仅加载本机轻量配置（<1ms），将原生中文名挂载与后台插件库增量恢复延迟至主窗口就绪后执行，不再拖慢 Blender 启动。
  - 若扩展仓库与脚本目录已匹配，启动恢复直接跳过昂贵的 `refresh_blender()` 全库重扫。
  - 原生名称映射（`native_names`）、挂载状态与目录检查（`bridge.library_state`）、面板刷新（`items.maybe_rebuild`）及本机配置读取统一加入 TTL / stat 缓存，彻底消除打开「偏好设置 → 插件 / 获取扩展」及滚动界面时对网络盘的同步阻塞；后台同步定时任务在无变化时零磁盘/网络 I/O。

## 2.5.0 变更

- **分类与工作预设彻底拆分**：
  - **分类筛选（Category）**：仅负责整理与筛选（含默认「全部插件」行），取消分类行上的开关/自启/常驻/独占按钮，点击只切换筛选，绝不误触发启停。
  - **工作预设（Preset）**：精选插件的一键启停与工作流切换（支持新建、从现有分类导入、从当前已启一键保存、常驻保护、按预设筛选、独占切换）；预设状态由成员真实启用情况实时推导（全开 / 部分开 / 未开），不再存在过期的死开关；开启预设时自动跳过已知不兼容或加载失败的插件。
- **二选一统一启动策略**：偏好设置新增明确二选一「启动模式」（持久化于本机 `machine.json`）——「记住上次状态」自动恢复退出前启用的插件，「干净启动」启动时一步到位仅加载自启预设与自启插件（临时启用的插件重启后自动恢复清爽，且不强关 Blender 内置插件），彻底消除旧版两次覆盖冲突。
- **手动单开提示与临时保护**：在侧栏或 Blender 原生界面手动启用插件后，面板温和提示「加入预设… / 归入分类… / 仅临时使用」；标记为本次临时使用的插件在切换或关闭其他预设时自动保留不被误关。

## 2.4.4 修复

- 外部插件收编新增扫描 Blender 默认用户插件目录（`scripts/addons`）与默认本地扩展仓库（`user_default`），自动过滤更新残留备份目录（如 `*_backup_temp`）与管理器自身；收编默认移动并自动停用源模块，避免原位置重复显示。
- 扫描/收编明细同步写入扫描报告并自动刷新列表；主面板底部拆分显示库内插件数、内置链接数与缺失数，计数更直观。

## 2.4.3 优化

- 新增基于元数据文件指纹的增量扫描：启动恢复与刷新时仅解析新增或改动过的插件，跳过未变更插件的文件读取与 AST/TOML 解析（网络盘扫描显著提速）。
- 启动恢复且已是插件库时跳过根目录散放文件探测，并修正后台状态文案：仅存在旧版 `library.json` 时才提示迁移旧资料库。

## 2.4.0 变更

- **插件工作分组（统一替代并无缝迁移旧分类）**：支持多对多分组归属、多组同时叠加开启/关闭（关闭时自动保留与其他开启分组共有的插件）、常驻基础组与独占切换，以及分组级自启同步；分组定义跨设备共享，组开关与自启保留在本机。

- **Blender 内置插件虚拟链接与冲突防护**：自动以只读虚拟链接纳入 `addons_core/` 自带插件以支持中文命名与分组管理，不复制进库、不可移入回收站、停止管理不误关内置插件；导入与收编自动拦截同名内置冲突。
- **侧边栏与偏好界面重构**：主面板聚焦工作分组与精简插件列表（批量复选框按需显示、详情默认展开），消除重复入口，偏好设置按四类清晰分区并统一术语。

## 2.2.0 变更（2026-09-18）

- **新增独立的总插件数据库** `.pm/catalog.json`，以稳定 `plugin_id` 为键保存可跨电脑同步的插件资料，取代旧版按库内相对路径为键的 `library.json`。
- 扫描时按 manifest id / 插件声明名 / 目录名自动匹配本机插件到总资料库条目：目录改名或插件改名后仍能连回，别名与分类不丢。
- 新增两条防误连规则：扩展与传统插件互不匹配；声明名冲突时不认目录名，避免同一目录换插件后错误继承别名。
- 本机安装位置改为 `plugin_id → 相对路径` 绑定，保存在本机状态目录；各电脑可用不同目录名与盘符。
- **自启标记从共享数据改为本机数据**：各电脑安装的插件不同，自启不再随总资料库同步，避免互相覆盖。
- 总插件数据库拒绝写入任何本机字段（路径、模块名、启用状态、自启）；读取时丢弃同步来文件中的未知/本机字段，不会因一个多余字段而整库只读。
- 移除插件只解除本机绑定，总资料库条目与其它电脑不受影响，重装后自动连回。
- 旧版 `library.json` 在首次连接时自动迁移（保留别名、分类、标签、备注、收藏；自启转入本机状态），旧文件归档为只读。
- 新设备首次连接时不再在总资料库中凭空创建空条目。
- 验证（Blender 5.2.1 LTS，隔离运行）：Python 单元测试 77 项通过（1 项按运行条件跳过）；Blender 隔离回归 31/31 通过；Blender 隔离端到端 186/186 通过；UI 冒烟无错误。运行前后真实 `userpref.blend` 未被改动。
- 实测中发现并修复：扫描路径误把目录名当作插件声明名；导入时补齐用户字段后回写旧引用导致备注等字段丢失；多个数据句柄先后保存同一文件时的并发误判。

## 2.1.0 变更（2026-09-15）

- 兼容性测试改为计时器驱动的分步任务：每个计时器事件只测试一个插件，事件之间把控制权交还 Blender，因此测试期间界面保持可交互。
- 侧栏显示 `已完成 / 总数`、当前插件名与进度条；状态栏同步显示进度；任务运行时「一键测试」按钮变为「取消」。
