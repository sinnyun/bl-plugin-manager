# 插件列表兼容性信息设计

## 目标

在插件列表每一行的名称右侧显示当前 Blender 版本的兼容性和插件声明的最高支持版本；隐藏插件自身版本号，避免列表信息拥挤。

## 现状

- `items.rebuild_items()` 已根据 `scan.blender_compat()` 实时计算 `item.compat`、`item.compat_detail`、`item.compat_text` 和 `item.max_version_text`。
- `ui.PM_UL_plugins.draw_item()` 当前只在右侧显示 `✓/✗/?`，没有显示兼容性文字和最高版本。
- 详情面板继续保留完整的插件版本、支持范围和最高版本信息，不在本次范围内删除。

## 设计

列表行右侧使用一个紧凑的纵向列，仅展示两类信息：

1. 当前 Blender 兼容性与启动实测：
   - `✓ 已实测可启动`：真实加载测试成功；
   - `✗ 启动测试失败`：真实加载测试失败；
   - `✗ 当前 Blender 不兼容`：当前版本低于最低要求或高于最高限制；
   - `? 声明兼容，未实测`：声明范围允许当前版本，但尚未真实加载；
   - `? 未声明，未实测`：插件未声明版本范围，且没有实测结论。
2. 最高支持版本：
   - 有上限时显示 `最高 ≤ 5.0.0`；
   - 没有上限时显示 `最高 不限`。

`load_state` 的实测结果与声明范围分开处理：未实测不再推导为 `supported=yes`，避免把无法启动的插件显示成可用。颜色沿用现有 `sub.alert` 规则，仅对不兼容/失败状态使用警示色。

## 数据流

`LibraryDB` 记录 → `items.rebuild_items()` 实时计算 → `PM_UL_plugins.draw_item()` 渲染。当前 Blender 版本通过 `scan.blender_compat()` 使用 `bpy.app.version` 获取，不新增持久化字段，也不改变过滤与详情逻辑。

## 验收标准

- 列表不再显示插件自身版本号。
- 每行都能看到当前 Blender 的兼容性结论和最高支持版本。
- `≤ x.y.z`、`不限`、`?`、不兼容等边界状态分别可渲染。
- 兼容性图标、更新图标、缺失/加载失败图标原有行为不回归。
- UI 静态检查、回归测试、Blender MCP 真实绘制测试全部通过。
