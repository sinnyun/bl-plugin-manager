# 插件库范围接管设计

用户已确认：接管全部扩展仓库、插件启用意图及自定义脚本目录。停止接管时仅将这三个范围恢复为当前 Blender 版本默认值；重新接管时恢复库的配置。主题、键位、语言、系统、渲染、资产库及启动文件不属于管理范围。

## 数据与设备

本机 machine.json 持久保存随机生成的设备 ID；保存路径或修改设备名称不得更换 ID。设备名称可编辑。设备配置按设备 ID 存放在库内独立 JSON 文件，避免两个电脑写整份数据库时互相覆盖。设备配置属于共享库的一部分，插件分类等仍在 library.json。绝对目录绑定只出现在对应设备的独立文件中；认证信息不进入共享库。设备数量不硬限制为三台。

设备启用意图与实际加载结果分开：缺少文件或加载失败不得删除启用意图。停止接管前保存意图，再停用插件；停止动作不能被同步器解释成用户清空清单。新设备不采用另一设备的启用清单。

## 配置接管

仓库逻辑信息包括稳定标识、名称、远程 URL、启用状态；每个仓库使用独立目录，避免不同来源同名扩展混淆。用户在原生仓库和脚本目录面板的修改由主线程同步器检测并写入管理数据。脚本目录仅绑定本机。库内修改反向应用到原生配置，使用重入保护和字段变更比较避免反馈循环。

仅在用户实际开启接管后执行恢复默认；单纯安装、注册管理器或库路径不可访问不能删除现存仓库与路径。停止状态必须持久保存，重启不能擅自重新接管。受控状态包括 INACTIVE、ACTIVATING、ACTIVE、DEACTIVATING、ERROR。

## 安全边界

禁止调用 read_factory_settings、read_homefile、read_userpref 或 save_userpref 来完成接管。禁止复制、覆盖 userpref.blend。禁止自动修改联网开关。默认值通过匹配 Blender 版本的隔离环境读取三项白名单数据；不得将工厂配置写回用户环境。默认插件不简单假定为全停用，保留 Blender 必需及默认组件和管理器本身。

旧的按名称猜测并清除挂载的逻辑需要退出；没有可靠所属信息时保留条目并报告。旧“统一商店”操作不应执行隐式文件迁移或清理未成功导入的源目录。

## 验证与交付

所有 Blender 测试在预先创建的独立配置、脚本、扩展和本机状态目录运行，启动后验证实际解析目录，不匹配即失败。测试使用 python-exit-code 传播异常。真实偏好只通过文件哈希验证未改动，禁止通过正常后台启动验证。

验收包括三设备独立列表、设备重命名保持 ID、停止后重新接管、原生面板双向同步、缺失插件保留意图、未接管时零修改、非受控偏好哨兵保持原值及多版本默认值恢复。
