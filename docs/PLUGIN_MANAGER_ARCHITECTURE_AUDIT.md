# 插件库管理器 2.0 架构审计与优化结果

## 结论

本轮已将插件从“把绝对路径和运行状态混入 Blender/共享配置”的旧结构，改为“共享库数据 + 本机身份 + 按设备配置 + 本机运行状态”四层结构。插件只接管扩展仓库、库内插件启用状态和自定义脚本目录。停用时不再读取工厂启动文件、覆盖 `userpref.blend` 或保存全部 Blender 偏好。

当前实现面向全新 schema 2 数据库，不将旧数据模型带入运行路径。

## 已修复的高风险缺陷

| 缺陷 | 结果 |
|---|---|
| 多电脑同步覆盖不同盘符 | 库路径移入本机 `machine.json`，Blender 属性使用 `SKIP_SAVE` |
| 设备身份随保存变化 | 首次生成 UUID，后续路径/名称修改保持不变 |
| 别名、分类无法随库迁移 | 便携字段保存在 `<库>/.pm/library.json` |
| 启用状态在不同电脑互相覆盖 | 每台设备使用 `<库>/.pm/devices/<device-id>.json` |
| 缺失插件被从启用清单删除 | 同步只更新本机实际扫描到的键，未知键保留 |
| 安装/加载管理器就擅自接管 | `management_enabled` 明确持久化；停止状态不会隐式恢复 |
| 停用时影响全部 Blender 设置 | 只重置扩展仓库、自定义脚本目录、库内插件启用状态 |
| 工厂重置或全局偏好保存破坏设置 | 源码禁止调用四个危险操作，静态测试持续检查 |
| 自动开启联网访问 | 改为只读取状态并提示用户，绝不赋值 |
| 按名称猜测并删除“孤儿挂载” | 旧启停与猜测清理入口已删除 |
| 官方仓库恢复点跨电脑污染 | 不再创建官方仓库偏好快照，停止时按受管字段恢复默认 |
| 数据库缓存命中同步旧文件 | 签名包含设备、inode、ctime、mtime、大小 |
| 数据库相对路径逃逸库外 | 读写/更新/删除统一验证容器边界 |
| 损坏数据库被空数据覆盖 | 损坏状态只读，拒绝保存 |
| 安装中断留下半个版本 | 临时目录编译后交换，并保留上一版本用于回滚 |

## 目标数据架构

```text
共享插件库
├── addons/、extensions/、inbox/、trash/
└── .pm/
    ├── library.json             共享便携元数据，schema 2
    ├── devices/<uuid>.json      每设备启用意图与本地绑定
    ├── backups/
    └── archive/

本机 LOCALAPPDATA
├── machine.json                 UUID、设备名、库路径、接管状态
└── state/<library-id>/<env>.json
                                模块、当前加载、兼容性与错误
```

共享主数据库不允许出现绝对路径。设备配置位于共享库中是有意设计：它需要随库同步，但每个设备只写自己的文件。设备身份文件位于本机，不能交给同步软件同步。

## 接管状态机

### INACTIVE

- 管理器可以显示路径，但不修改原生配置。
- Blender 启动或管理器重新加载不会自动接管。
- 原生配置不存在“按名称清理”的副作用。

### ACTIVATING / ACTIVE

1. 初始化并扫描 schema 2 库。
2. 新设备从当前原生仓库、脚本目录和库内插件状态建立自己的配置。
3. 已知设备应用自己的配置。
4. 强制保持库根脚本目录和库扩展目录两个必需绑定。
5. 每两秒比较受管字段；只有变化时才原子写入设备文件。
6. 原生面板新增的自定义仓库、脚本目录和库内插件启停进入当前设备配置。

### DEACTIVATING / ERROR

停止前先同步，之后停用库内插件、清空自定义脚本目录、移除自定义仓库并恢复官方仓库默认字段。Blender 内置仓库和管理器本身保留。单项失败会进入 `ERROR` 并返回明细，不报告虚假成功。

## 精确安全边界

允许写入：

- 当前插件库目录及其 `.pm` 数据；
- `%LOCALAPPDATA%/BlenderPluginManager`；
- 当前 Blender 进程内的扩展仓库集合、自定义脚本目录集合和库内插件启用集合。

明确禁止：

- `bpy.ops.wm.save_userpref()`；
- `read_factory_settings`、`read_homefile`、`read_userpref`；
- 写入或替换任何真实 `userpref.blend`；
- 修改联网权限、主题、快捷键、语言、界面、系统、渲染、资产库或启动文件；
- 未验证路径上的递归删除或移动；
- 根据显示名称推测条目归属。

## 同步策略

- 共享元数据和设备配置均使用 UTF-8 JSON、临时文件、刷新和原子替换。
- 设备文件按 UUID 分片，避免三台电脑同时保存各自启用清单时覆盖同一文件。
- 修改设备名称只更新名称，UUID 不变。
- 运行状态以 `library_id + 环境指纹` 隔离，不会把一台电脑的模块路径或加载失败写给另一台。
- 同步工具发生同一设备文件冲突时保留显式冲突文件；插件不会吞掉损坏 JSON 后重建覆盖。

## 测试与证据

- 普通 Python 单元测试覆盖设备身份、设备配置、状态机、数据库安全、路径边界和危险 API 静态约束；最终结果为 40 项通过，1 项按运行条件跳过。
- Blender 回归测试覆盖受管范围恢复、官方仓库默认字段、在线权限哨兵及挂载状态缓存；最终结果为 16/16 通过。
- Blender 端到端测试覆盖初始化、导入、扫描、启停、分类、别名、更新、迁移、停止/重启/显式恢复和非活动零修改；最终结果为 166/166 通过。
- 两套 Blender 启动器都设置独立配置、脚本、TEMP、本机配置和本地状态目录，并在 Python 入口验证解析后的真实路径。
- 2026-09-15 最终验证前后，真实 Blender 5.2 `userpref.blend` SHA-256 均为 `6015931B9E7BF51E647A18CECD921C6A79FE33063EA224BF814EB751E631B5ED`。
- 发行 ZIP 包含 29 个文件，不含缓存和编译产物；SHA-256 为 `B12ACCD17A6CFC7FEA878A379B5764BD2874F7C58DA4E79C45C00C82904071FF`。
- Blender 4.5 与 5.2 的已安装目录分别与源码逐文件核对，29/29 文件一致。

## 仍需遵守的运行约束

- 兼容性实测会执行第三方插件的 `register()`，第三方代码自身仍可能报错或产生副作用；应只测试可信插件。
- 网络下载和部分大库扫描仍可能占用 Blender 主线程。当前通过超时、状态提示和原子写入降低风险，但后续版本可继续拆成可取消后台任务。
- Blender 新版本若改变官方仓库字段，应先在隔离环境更新适配测试，再扩大支持版本；不能通过加载真实用户配置来探测默认值。

## 交付验收

- 不同设备路径、名称和启用清单互不覆盖。
- 共享别名、分类、备注与库一起迁移。
- 管理器停止后原生三项范围恢复默认，其它偏好哨兵不变。
- 重新加载保持停止；显式启用后恢复当前设备清单。
- 原生面板更改可同步，必需库绑定不会被永久删掉。
- 缺失或加载失败插件保留启用意图。
- 隔离单元、回归和端到端测试全部通过后才生成安装包。
